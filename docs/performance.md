# 性能与体积优化记录

日期：2026-11-13。本记录对应 v0.16（包版本 `0.16.0`）的性能与体积优化。

## 运行时

- 曲库、收藏夹、队列内容和设置仅在变化时传给窗口。日常进度消息只发送进度和曲目 ID，由窗口内的缓存还原当前曲目。
- 隐藏或最小化的窗口不接收刷新，恢复显示时立即同步。悬浮窗关闭时，启动阶段不创建它的渲染进程。
- 同一轮事件中的状态广播合并发送；播放轮询不再并发重叠。
- 收藏和专辑查询使用索引；普通进度刷新跳过列表和快捷键区域重建。
- 悬浮窗位置在拖动结束后合并保存，退出前写入最后位置；重要曲库操作仍立即保存。内容未变化时不重复写盘。

## 测量方法

运行 `npm run bench:runtime`。基准启动一个使用隔离配置的隐藏 Electron 窗口，加载真实主界面和预加载桥；构造 300 张专辑、12000 首歌、2000 条收藏与完整队列，连续发送 60 次进度更新，等待真实渲染完成。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 日常单次进度数据（JSON 字节） | 1,190,107 | 420 |
| 60 次更新合计数据（包含首次曲库同步） | 71,406,402 字节 | 1,211,023 字节 |
| 60 次更新总耗时 | 5,959 ms | 130 ms |

结果来自本机单次对照，耗时会受机器、缓存及其他任务影响。数据字节数按 JSON 计算，不是底层 IPC 传输的精确字节数；该基准不代表视频网络加载或所有应用操作的提速比例。再次运行会生成被 Git 忽略的 `tools/perf-after.json`。

## 便携包

保留完整 Electron 运行 DLL、GPU 回退组件、字体和媒体运行资源及许可证。仅精简非运行必需的默认示例、README 截图和其他语言资源，保留 `en-US`、`zh-CN`、`zh-TW`。语言资源本身减少约 41 MiB。

打包使用包内 exe 检查中文、英文和其他语言回退下的启动，不依赖开发机 Node.js/npm。SHA256 通过流式读取计算，避免额外将整个 ZIP 载入内存。`dist/pack-report.json` 记录实际 ZIP、解压体积和上一次打包体积。

本次重建结果（MiB，1 MiB = 1048576 字节）：

| 体积 | 优化前 | 优化后 | 减少 |
|---|---:|---:|---:|
| ZIP | 129.4 MiB | 117.6 MiB | 约 9.1% |
| 解压目录 | 319.5 MiB | 277.0 MiB | 约 13.3% |

包内程序的中文、英文、法语回退启动检查通过；直接运行包内程序的悬浮窗及隐藏窗口恢复检查通过。ZIP 校验和、运行 DLL、许可证、赞助二维码和代码一致性检查通过。

Electron 的运行时仍占主要体积；本次没有通过移除运行 DLL 或更换桌面框架来换取更小的包。

## 验证

`npm run test:all` 覆盖状态往返、初始消息丢失、过期响应、收藏与队列变更、配置保存及发布过滤；`npm run test:folder`、`npm run test:ui`、`npm run test:mini-toggle` 检查界面和隐藏窗口恢复；`npm run test:pause-cdp` 验证曲尾接歌与手动暂停。真实 B 站画质对照可运行 `npm run test:quality-live`。
